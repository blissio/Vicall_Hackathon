# Five-minute demonstration

Use `python demo.py` and `python app.py --data-dir demo_data`. State clearly that the offline records and findings are fictional. For a real demonstration, substitute a reviewed dataset and disclose its sample size.

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:35 | Directory | Useful business information is scattered. Reece needs offices and districts, while other users need local providers and partners. |
| 0:35–1:30 | Research assistant: accounting + public contact + technical issues | Exact constraints retrieve an explained shortlist from saved evidence. Blocked checks remain inconclusive. |
| 1:30–2:20 | Profile, sources, role review, shortlist/export | Sources and dates survive collection updates. A public role is not assumed purchasing authority. |
| 2:20–3:00 | School district and child school | Organizations and locations are separate; district contacts need the right organizational level. |
| 3:00–3:40 | Provider query: legal advice | The directory supports buying services as well as prospect research. |
| 3:40–4:25 | Optional AI answer or saved evidence fallback | AI interprets a bounded retrieved context. References are checked; human review still determines factual support. Without configured AI, describe this as evidence search. |
| 4:25–5:00 | Evaluation report | Four synthetic scenarios, explicit baselines, local retrieval latency, context characters, and zero external page requests. These results demonstrate the workflow, not real prospect quality or token savings. |

Before presenting, rehearse with the exact machine and dataset. Keep a saved evidence export and screenshot available. Do not run live citywide collection during the five-minute presentation.
